TOP-X VERCEL DEPLOY NOTES

This archive contains the main TOP-X Next.js app at the root and the separate admin Next.js app in /admin.
Do not upload .env.local or commit secrets. Configure environment variables in Vercel Project Settings.

MAIN APP:
- Import/upload the TOP-X-Vercel-Ready folder as the main Vercel project.
- Framework preset: Next.js
- Root Directory: ./
- Install: npm install
- Build: npm run build
- Node.js: 20.x or newer
- Configure the environment variables from .env.example. Set DATABASE_URL to your production PostgreSQL/Supabase connection string, ADMIN_KEY, SESSION_SECRET, APP_ORIGIN, and any Firebase/Google OAuth values actually used by your deployment.
- APP_ORIGIN must be the deployed main app URL. Set OAuth authorized origins/redirect URLs to the deployed domain where applicable.

ADMIN APP (separate Vercel project, same backend):
- Create a second Vercel project using this same uploaded source.
- Set Root Directory to admin/
- Framework preset: Next.js
- Install: npm install
- Build: npm run build
- Set NEXT_PUBLIC_API_BASE_URL to the deployed MAIN app URL (no trailing slash), then redeploy.
- Configure any admin-specific environment variables required by admin code.
- This keeps the admin frontend separate while using the main app's API/backend.

IMPORTANT:
- Vercel deployments do not make local JSON files persistent storage. Use PostgreSQL/Supabase for production data.
- The main app and admin app are two separate Next.js applications, so they need two Vercel projects/deployments. A single deployment will not host both as independent apps automatically.
- For deployment without GitHub, use Vercel CLI from a terminal:
    npm install -g vercel
    cd TOP-X-Vercel-Ready
    vercel
  Follow prompts, then configure environment variables in the Vercel dashboard and run:
    vercel --prod
  For the admin deployment, run `cd admin` and repeat `vercel`, linking it as a separate project.
